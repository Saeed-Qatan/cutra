# القرارات والحالة

آخر تحديث: 2026-10-10

## القرار الحالي المعتمد

بناء Cutra يبدأ بالـtheme الذي سيرسله مالك المشروع، ثم تحويل HTML/CSS لكل صفحة إلى Flutter. تُنجز UI/UX وbusiness logic المحلي لكل صفحة وفق MVVM وRiverpod قبل الانتقال إلى التالية. يبدأ التسلسل بـSplash ثم Home، ويأتي تكامل backend بعد اكتمال جميع الصفحات والمنطق المحلي. الترتيب التفصيلي وحالة التنفيذ في `TASKS.md`.

## الحالة الحالية

- يوجد أساس Flutter مع Riverpod وGoRouter وDio وStorage، وشاشات Auth وHome أولية.
- يوجد منطق Cutting v1 كسجاد 2D على رول ثابت العرض بوحدة mm، مع `kerfMm` ودوران اختياري، وخوارزمية pure Dart واختبارات.
- لم يصل theme وHTML/CSS الجديد بعد. لا تعد الشاشات الحالية مكتملة وفق معيار التصميم الجديد حتى تُراجع وتُربط بمنطقها المحلي.
- عميل Dio وعقود Auth الموجودة عمل سابق؛ تُراجع مقابل backend الفعلي في المرحلة الأخيرة. ليست مصدر البيانات المعتمد للصفحات الجديدة الآن.
- حُذف `lib/core/config`؛ لا يُدرج ضمن المعمارية المستهدفة.

## قرارات تقنية قائمة

- `agents/` هو مجلد التعليمات داخل المشروع، و`TASKS.md` مرجع المهام.
- Feature-first architecture وSOLID، مع تدفق MVVM وRiverpod المحدد في `ARCHITECTURE.md`.
- GoRouter للتنقل، Secure Storage للبيانات الحساسة، SharedPreferences للتفضيلات، وFreezed/json_serializable عند الحاجة.
- البحث عن مكتبة مستقرة قبل بناء حل مخصص معروف، وتوثيق أي dependency جديدة.
- لكل ميزة فرع وعملية تحقق وتسليم وفق `Feature.md` و`GIT_BRANCH_WORKFLOW.md`.
